# Uncertainties

Decisions made while implementing without the user around. Each lists the options considered, the pick, and why. Revisit any of them; none is hard to change yet.

## Spark format (#1)

**Absent text: `null` or omitted field?** Options: allow omitting `note`/`quote`/`selection`/`title`; require every field with `null` for absent. Picked: every field required. One canonical shape means one comparison for the server's same-id check and no "missing vs null" branches in three languages.

**Whitespace around Note, Quote and title.** Options: server trims; schema rejects untrimmed text; accept anything. Picked: reject untrimmed text, so the extension must trim before sending. The server never rewrites what it was sent, and the Inbox holds exactly what the extension showed. Selection is the exception, since it's raw page text by definition.

**UUID case.** Options: any case; lowercase only. Picked: lowercase, which is what `crypto.randomUUID()` produces. Same-id checks can then compare strings directly.

**Duplicate JSON keys.** Options: ignore (last wins, as serde_json and JSON.parse do); reject. Picked: reject in the server with a strict parser, since Python and some other parsers disagree on which value wins. The extension only validates JSON it produces from an object, so its tests skip that fixture.

**`captured_at` format.** Options: any RFC 3339 offset; UTC with `Z` only. Picked: `Z` only, matching `toISOString()`, so timestamps sort as strings.

**Fixture files.** Options: hand-written files; generated by a script. Picked: `spec/make_fixtures.py` generates them from a base Spark plus one change per case, and the pre-commit hook checks they're current. The 64 KB boundary cases need exact byte counts, which are easy to get wrong by hand.
